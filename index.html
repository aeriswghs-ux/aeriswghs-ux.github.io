Wind tunnel & instrumentation

A two-fan tunnel, a plexiglass test body, and a move from smoke to dry-ice flow visualization. The current focus is the sensor system and load-cell calibration.

Sensor integration / Load-cell calibration

Latest build update / Reported by Rithwik

The setup changed. So did the approach.

One fan at the inlet and another at the outlet move air through the tunnel. The inlet and outlet use 3D-printed parts; the main body combines plexiglass with printed supports.

The setback

The smoke system led to repeated changes in materials, filaments, air pumps, and the overall setup.

The change

Rithika proposed switching to dry ice. Rithwik reports that the resulting cold-air visualization now works smoothly. This is a build observation, not a measured flow-uniformity result.

The next measurement

The sensor system is being built around two load cells with HX711 interfaces for lift and drag, a differential-pressure sensor, and a BME280. Load-cell calibration remains unfinished.

This account is a user-provided update beyond the reviewed repository snapshot. New photos, wiring, calibration records, and measured results have not yet been supplied. The exact pressure-sensor model still needs confirmation.

InstrumentationA

A record of what the sensors see.

The earlier repository logger brings a BME280 environmental sensor, a modeled differential-pressure channel, and SD storage into one Arduino program. Its loop schedules a CSV record every two seconds and keeps raw and conditioned pressure fields separate.

Data toolsC

From a CSV to a question.

The Python grapher reads environmental channels and creates plots. A separate Flask prototype explores offset correction, summary statistics, and CSV export. These are tools for examining data; their presence does not validate the underlying measurements.

Why calibration remains an open question

The correction prototype contains default offsets, but the repository does not supply a reference-calibration record establishing them. Adjusting an offset is a software operation; demonstrating accuracy requires independent measurements.
